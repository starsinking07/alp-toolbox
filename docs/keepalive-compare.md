# 保活周期 (0.4s vs 4.0s) 对比结论

**日期**: 2026-10-23 · 固件 3.0.3 · USB · 目标 1400/1800/2200 rpm · 每档稳定 8s + 采样 5s · 打乱顺序跑两轮

## 结论: 保活周期不是"转速偏差"的来源

| 目标 | ka=0.4s | ka=4.0s | 差 |
|---|---|---|---|
| 1400 | 1785 | 1785 | 0 |
| 1800 | 2070 | 2145 | +75 |
| 2200 | 2475 | 2400 | −75 |

差值有正有负、量级 ±75 rpm，落在重复测量的噪声内（同一目标两轮之间就能差 150 rpm）。
⇒ **不采纳**"把保活放宽到 4s 以减小偏差"的方案，`KEEPALIVE_S = 0.4` 保持不变。

## 真正的偏差来自设备端的压缩映射

三轮独立标定（本次两轮 + 2026-10-21 一轮）结论一致：
**实测 ≈ a × 目标 + b，其中 a < 1、b > 0** —— 低速被抬高、高速被压低。

本次拟合 a = 0.769~0.863、b = 557~726；偏差随目标增大而收窄：
1400 → +22~33% / 1800 → +13~20% / 2200 → +8~13%。

所以"固定偏移 −200"必然不成立（低速有效、高速过冲），要准只能闭环 ——
即工具箱已有的 `rpm_trim_mode = loop`（死区 ±60、每 5s 调 60、约 30s 收敛）。

## 附注: 本次修掉的工具 bug

`--shuffle` 下 `results[ka]` 按**执行顺序**追加，旧对比表却按 `targets[i]` 取值，
整张表会错位（首跑把目标 1400 显示成 2160）。已改为按 `target` 字段归并、多轮取中位。
